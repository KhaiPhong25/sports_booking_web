# Phase 7–8 Queue, Notifications and Customer Web Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Hoàn thiện queue/notification bền vững và trải nghiệm customer đầy đủ của Sports Booking MVP đến hết Phase 8.

**Architecture:** Booking transaction ghi notification và outbox event trong PostgreSQL. Worker relay dùng BullMQ job ID ổn định; lifecycle/email processors kiểm tra durable state để retry hoặc chạy lặp vẫn an toàn. Web tiếp tục là Vite vanilla ES modules, thêm notification page và Leaflet sau một replaceable map adapter.

**Tech Stack:** NestJS, Prisma/PostgreSQL, BullMQ/Redis, `pg`, Nodemailer/MailHog, Vite/vanilla JavaScript, Leaflet, Jest/Vitest/Supertest, Docker Compose.

**Spec:** `docs/architecture/design-spec.md`

## Global Constraints

- PostgreSQL là durable source of truth; Redis không lưu booking vĩnh viễn.
- Notification/outbox phải commit cùng mutation booking; SMTP lỗi không rollback booking.
- Worker dùng event/job ID ổn định, transition có expected status và ghi history đúng một lần.
- API chỉ cho principal đọc/mark-read notification của chính mình.
- UI tiếng Việt, semantic, responsive, có loading/empty/success/error và keyboard focus.
- Không stage `AGENTS.md`, `CODEX_PROJECT_CONTEXT.md`, `prompt.md` hoặc blueprint.
